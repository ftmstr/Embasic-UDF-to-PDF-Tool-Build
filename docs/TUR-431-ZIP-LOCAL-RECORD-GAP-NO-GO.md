## New independent Java 21 source-fidelity failure
A rights-clean Java ZipOutputStream UDF with one synthetic `content.xml` has LOCAL member data, then CENTRAL records, then EOCD. Inserting ASCII hidden content *after the last LOCAL data descriptor but before CENTRAL*, increasing the EOCD recorded CENTRAL offset to match, yields a ZIP whose EOCD ends exactly at EOF and all original LOCAL/CENTRAL members still match SHA-256/CRC. OpenJDK21's `ZipFile` and `ZipInputStream` independently return identical visible XML while silently omitting the interstitial bytes. TUR430's EOCD/tail check cannot detect this placement; successful PDF would drop source bytes.
